# مرحله ۳ — انتقال بقیه‌ی داده‌های لوکال به سرور

## چه چیزی منتقل شد (در حالت API)
| داده | قبلاً (localStorage) | حالا |
|---|---|---|
| تاریخچه/فلش جابه‌جایی رتبه‌ی نمایشگاه‌ها | `carmaa_showroom_rank_history_v1` | `GET /api/v1/showrooms/rank-movements` — رتبه‌ها سمت سرور از آگهی/دنبال‌کننده/امتیاز محاسبه و در جدول `showroom_rank_snapshots` نگه‌داری می‌شود (کش ۶۰ ثانیه) |
| تاریخ عضویت نمایشگاه | `carmaa_showroom_joined_v1` | `showrooms.created_at` (بدون جدول جدید) |
| «دیده‌شده» بودن استوری | `marque_stories_seen_v1` | جدول `story_seen`؛ `POST /social/stories/:id/seen` و فیلد `seen` در `GET /social/stories` (برای کاربر واردشده) |
| slug عمومی نمایشگاه | `marque_dealer_slugs_v1` | `showrooms.slug` سرور |
| عکس پروفایل/بنر حساب (پیش‌نمایش) | `mr_avatars_v1` | فقط هنگام «ذخیره» به سرور آپلود می‌شود؛ دیگر در مرورگر ماندگار نمی‌شود |

- migration جدید: `backend/migrations/013_rank_history_story_seen.sql` (idempotent؛ `deploy.sh` اجرا می‌کند).
- حالت آفلاین/دمو (بدون API) مثل قبل با localStorage کار می‌کند.

## بررسی کل پروژه: چیزهایی که عمداً لوکال ماندند
- تنظیمات/کش سمت دستگاه: `mr_list_style` (نوع نمایش لیست)، `carma_news_covers_v2` (کش کاور خبرها)، `mr_auto_banner_v2` (بنر تصادفی نمایشی)، `mr_home_dashboard_migrated_v1`، `marque_story_device_v1` (شناسه‌ی ناشناس بازدیدکننده‌ی بدون ورود)، پیش‌نویس‌های sessionStorage (سؤال/پاسخ/فیلتر Q&A، کلید idempotency پرداخت).
- `carmaa_chat_att_v1` فقط کش اسنپ‌شات آگهیِ پیوست‌شده در پیام است؛ خود پیام و توکن آگهی روی سرور است.
- `mr_ad_stats_v1`: شمارنده‌ی لوکالِ پشتیبان؛ در پنجره‌ی «آمار آگهی» داده‌ی سرور (`/social/listings/:id/stats`) جایگزینش می‌شود.
- بقیه‌ی کلیدها (پیام‌ها، اعلان‌ها، پیشنهاد قیمت، گزارش، Q&A، لایک/کامنت خبر، هشتگ، نام کاربری، دنبال‌کردن، استوری، پنل ادمین `admin-panel.js`) از قبل در حالت API سروری بودند و فقط مسیر آفلاین/دمو از localStorage استفاده می‌کند. `admin.js` قدیمی دیگر در `admin.html` بارگذاری نمی‌شود.

## دیپلوی
1. محتویات zip را روی پوشه‌ی پروژه‌ی سرور بریز (بدون دست‌زدن به `backend/.env`) و `bash deploy.sh` را بزن. در لاگ باید `Applied migration: 013_...` ببینی.
2. کش مرورگر را پاک کن.

## تست‌ها
- `node --check` روی همه‌ی JS فرانت و بک‌اند و `node --test test/frontend-api-adapter.test.js`: موفق.
- **انجام نشد** (Postgres/مرورگر در این محیط نبود): اجرای migration 013 و کوئری‌ها روی دیتابیس واقعی، و تست مرورگر. روی سرور بررسی کن:
  1. `curl -s http://IP/api/v1/showrooms/rank-movements` → `{"movementsBySort":{...}}`
  2. بعد از تغییر تعداد آگهی/دنبال‌کننده‌ی یک نمایشگاه و ≥۶۰ ثانیه، فلش جابه‌جایی در صفحه‌ی نمایشگاه‌ها دیده شود.
  3. استوری را ببین، رفرش/مرورگر دیگر با همان حساب → حلقه‌ی «دیده‌شده» بماند.
  4. تاریخ عضویت نمایشگاه با `created_at` همخوان باشد.
- توجه: داده‌ی لوکالِ قدیمی (رتبه، seen) منتقل نمی‌شود؛ رتبه از اولین محاسبه‌ی سرور شروع می‌شود و استوری‌های ۲۴ ساعته به‌زودی منقضی می‌شوند.
