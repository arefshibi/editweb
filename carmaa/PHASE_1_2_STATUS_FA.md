# وضعیت اجرای مرحله‌های ۱ و ۲ — CarMaa

## نتیجهٔ صادقانه

این بسته شامل اتصال‌های فرانت‌اند و تست‌های کدی تکمیل‌شده در این دور است، اما اجرای کامل سرویس‌ها هنوز تأیید نشده است.

### مرحلهٔ ۱: محیط اجرا و یکپارچه‌سازی
- `npm test`: موفق، ۲۶/۲۶ تست
- `npm run check`: موفق، بررسی نحوی فایل‌های JS بک‌اند و تست‌ها
- بررسی نحوی فایل‌های JavaScript فرانت‌اند با `node --check`: باید روی همین بسته انجام شود و نتیجه در `CarMaa_validation_v3.txt` ثبت شده است.
- تلاش برای ساخت `package-lock.json` با `npm install --package-lock-only --ignore-scripts --no-audit --no-fund` به timeout خورد؛ فایل lock ساختگی اضافه نشده است.
- Docker/Podman، PostgreSQL و Redis در محیط اجرا در دسترس نبودند؛ بنابراین اجرای `docker compose up`, migration واقعی، `/health/ready` و تست API زنده انجام نشده‌اند.

### مرحلهٔ ۲: اتصال رابط کاربری
- ثبت و ویرایش آگهی و آپلود عکس از طریق پل `js/42-api-marketplace-bridge.js` به API متصل است.
- فهرست عمومی آگهی‌ها و آگهی‌های کاربر از API هیدراته می‌شود.
- نشان‌کردن آگهی اکنون در حالت API از endpoint سمت سرور استفاده می‌کند؛ دیگر برای آگهی‌های سروری صرفاً در `state.likedIds` ذخیره نمی‌شود.
- نشان‌شده‌ها پس از بازیابی نشست و پس از ورود موفق از API بارگیری می‌شوند.
- متدهای API برای علاقه‌مندی‌ها، پروفایل و جستجوهای ذخیره‌شده در client تعریف شده‌اند؛ وجود متد به‌تنهایی به معنی اتصال تمام فرم‌های مربوطه نیست.

## موارد باز برای بستن مرحلهٔ ۱
1. اجرای نصب dependencyها در محیط دارای دسترسی npm و commit کردن `package-lock.json` واقعی.
2. اجرای Docker Compose با secrets جدید در محیط staging.
3. اجرای migrationها روی دیتابیس آزمایشی و بررسی health readiness.
4. اجرای تست smoke فقط روی staging و تست APIهای مثبت/منفی با دو حساب آزمایشی.
5. اجرای بررسی dependency و SAST/DAST؛ هیچ‌کدام در این محیط ادعا نمی‌شود.

## موارد باز برای بستن مرحلهٔ ۲
- تکمیل فرم پروفایل تا تمام فیلدهای قابل‌ویرایش در قرارداد سمت سرور ذخیره شوند؛ ایمیل و نام کاربری فعلی هنوز قرارداد و persistence کامل سمت سرور ندارند.
- اتصال کامل صفحهٔ پرسش‌وپاسخ، پاسخ‌ها و انتخاب پاسخ پذیرفته‌شده به API؛ endpointها وجود دارند ولی تمام UI هنوز یکپارچه نشده است.
- اتصال کامل صفحهٔ نمایشگاه‌ها، دنبال‌کردن نمایشگاه، امتیازها و فرم مدیریت نمایشگاه به API؛ بخشی از مسیرها هنوز local/demo هستند.
- جایگزینی منبع محلی اعلان‌ها با endpoint اعلان‌ها و علامت‌گذاری خوانده‌شدن در UI.
- انتقال کامل پیام‌ها و offerها و وضعیت آن‌ها به API؛ وجود endpointها به معنی یکپارچگی همهٔ کنترل‌های قدیمی نیست.
- اتصال صفحه‌بندی/جستجوی فیلترشده به queryهای API؛ UI فعلی در برخی نقاط فقط ۵۰ مورد نخست را می‌خواند.
- حذف/جداسازی کامل داده‌های seed/demo از محیط production.

## فرمان‌های لازم در محیط staging
```bash
cd backend
cp .env.example .env
# مقادیر .env را با secrets یکتا و آدرس‌های staging تنظیم کنید.
docker compose config
docker compose up -d --build
npm ci
npm run migrate
npm test
npm run check
./test/staging-smoke.sh
```

اسکریپت smoke را فقط با URL محیط آزمایشی مجاز اجرا کنید؛ آن اسکریپت برای production نیست. قبل از اجرا، متغیرهای محیطی و مستندات خود اسکریپت را بخوانید.
