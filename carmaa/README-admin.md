# پنل مدیریت (admin.html)

باز کردن: `admin.html` کنار `index.html`. سایت و پنل هر دو از یک فروشگاه داده‌ی مشترک می‌خوانند و می‌نویسند.

## چه چیزی به سایت وصل است
| در پنل | اثر روی سایت |
|---|---|
| تایید آگهی | آگهی در `LISTINGS` منتشر می‌شود (صفحه‌ی اصلی، برند، جستجو) |
| رد آگهی با دلیل | صاحب آگهی در «مدیریت آگهی‌ها» دلیل را می‌بیند و می‌تواند اصلاح و دوباره ارسال کند |
| ویژه کردن | `promoted` آگهی عوض می‌شود |
| مخفی کردن / نمایش دوباره (آگهی‌های اولیه‌ی `01-data.js`) | از لیست‌های سایت برداشته یا برگردانده می‌شود |
| حذف (آگهی کاربر) | از سایت و از حساب صاحبش پاک می‌شود |
| محدود کردن کاربر | آن حساب نمی‌تواند آگهی جدید ثبت کند |
| تایید نمایشگاه | فقط علامت در پنل (هنوز نشانی در سایت ندارد) |
| تایید دستی آگهی‌ها (تنظیمات) | روشن: آگهی جدید منتظر تایید ادمین می‌ماند. خاموش: مثل قبل خودکار منتشر می‌شود |

آگهی‌های کاربر حالا با رفرش از بین نمی‌روند (در `localStorage` ذخیره می‌شوند).

## فایل‌ها
- `js/02a-admin-store.js` — `MR_STORE`: همه‌ی خواندن و نوشتن داده‌ی مدیریت از اینجا رد می‌شود.
- `js/23-admin-sync.js` — `mrApplyStore()`: تصمیم‌های ادمین را روی `LISTINGS` و آگهی‌های صاحب حساب اعمال می‌کند؛ با تغییر پنل در تب دیگر خودکار اجرا می‌شود.
- `admin.html`, `admin.css`, `admin.js` — خود پنل.
- هوک‌ها در سایت: `17-chip-dropdown.js` (ثبت، ویرایش، محدودیت کاربر)، `04-state-core.js` (حذف)، `06-home-cards.js`, `08-auth-modal-toast.js`, `15-pages-account.js` (نمایش وضعیت رد و انتظار)، `18-peek-preview-init.js` (اجرای اولیه).

## محدودیت‌های مهم (حتماً بخوان)
1. **فقط یک مرورگر.** داده در `localStorage` است؛ ادمینی که روی لپ‌تاپ خودش تایید می‌کند آگهی کاربر روی گوشی دیگری را عوض نمی‌کند. برای ادمین واقعی باید سرور داشته باشی.
2. **قفل ورود ندارد.** هر کس `admin.html` را باز کند وارد می‌شود (فقط روی مرورگر خودش اثر دارد). قبل از انتشار آنلاین حتماً ورود ادمین سمت سرور اضافه کن.
3. عکس‌های آگهی به‌صورت data URL در `localStorage` ذخیره می‌شوند (حدود ۵ مگابایت). عکس‌ها هنگام انتخاب به حداکثر ۱۲۸۰ پیکسل فشرده می‌شوند و اگر جا کم باشد، `mrPersistListing()` (در `23-admin-sync.js`) اول آن‌ها را بیشتر فشرده می‌کند و فقط در آخرین مرحله تعداد عکس‌ها را کم می‌کند — همیشه با پیام به کاربر، هیچ‌وقت بی‌صدا. راه‌حل اصلی: سرور و ذخیره‌ی عکس به‌صورت فایل.

## رفتن به سرور واقعی
فقط `read()` و `edit()` داخل `MR_STORE` را با فراخوانی API عوض کن (مثلاً `GET/PATCH /api/ads`, `/api/users`, `/api/settings`) و `mrApplyStore()` را بعد از هر پاسخ صدا بزن؛ بقیه‌ی کد سایت و پنل همان می‌ماند. به‌جای رویداد `storage` از polling یا WebSocket استفاده کن.

## چیزهایی که در این نسخه نیست
پوشاندن خودکار پلاک، گزارش آگهی توسط کاربران، مدیریت برند/مدل، بنر و پلن/پرداخت. صندوق پیام اکنون در فرانت‌اند اضافه شده، اما بدون بک‌اند فقط حالت پیش‌نمایش محلی دارد و پیام‌ها بین دستگاه‌ها ارسال نمی‌شوند؛ قرارداد اتصال در `CHAT_API_CONTRACT.md` است.
