# گزارش تکمیل اتصال‌های باقی‌مانده CarMaa — نسخه ۶

## تغییرات این مرحله

- امتیازدهی نمایشگاه در حالت آنلاین به API و دیتابیس وصل شد؛ دیگر امتیاز محلی مرورگر را به‌عنوان رأی سروری نشان نمی‌دهد.
- فرم تماس با پشتیبانی به API و جدول `support_tickets` وصل شد؛ ثبت درخواست محدودسازی نرخ دارد و برای مدیران اعلان ایجاد می‌کند.
- پاسخ به استوری از حالت سرورمحور به گفتگوی مستقیم واقعی منتقل شد: `POST /api/v1/messages/conversations/direct` گفتگوی مستقیم با کاربر فعال را ایجاد/بازیابی می‌کند و پیام پاسخ از API پیام‌رسان ارسال می‌شود.
- Migration شمارهٔ `005_direct_conversations.sql` امکان گفتگوی بدون آگهی را اضافه می‌کند و با ایندکس یکتا از ساخت چند گفتگوی مستقیم برای یک جفت کاربر جلوگیری می‌کند.
- پس از پذیرفتن پیشنهاد قیمت در حالت سرور، UI برای ایجاد/بازکردن گفتگوی خریدار تلاش می‌کند؛ اعلان پیشنهاد اکنون شناسهٔ سروری خریدار را نیز حمل می‌کند.
- استوری‌های نمایشی دیگر در حالت API سخت‌گیرانه با استوری‌های سرور مخلوط نمی‌شوند.
- در حالت API، دنبال‌کردن شناسه‌های محلی/نمایشی به‌صورت محلی ذخیره نمی‌شود؛ اگر حساب به سرور متصل نباشد، UI پیام روشن می‌دهد.
- در صورت خطای ثبت بازدید استوری، تلاش بعدی مسدود نمی‌شود.
- محدودیت ۱۰ استوری فعال برای هر حساب با قفل تراکنشی محافظت می‌شود تا درخواست‌های هم‌زمان از محدودیت عبور نکنند.
- حذف حساب‌های غیرفعال/حذف‌شده از فهرست عمومی استوری‌ها.

## محدودیت‌های باقیمانده

این محیط به PostgreSQL، Redis و مرورگر staging متصل نیست و دسترسی به npm registry نیز در اجرای قبلی با خطای DNS روبه‌رو شد. بنابراین Migrationهای ۰۰۱ تا ۰۰۶ روی دیتابیس واقعی اجرا نشده‌اند؛ جریان‌های دوحسابی، SMS، پرداخت sandbox، تست E2E مرورگر، تست نفوذ واقعی، backup/restore و بررسی نهایی امنیتی در staging هنوز باید اجرا شوند. موفقیت تست‌های خودکار به معنی تأیید عملیاتی کامل نیست.

## دستور اجرای محیط آزمایشی

از پوشه `backend` و پس از تنظیم `.env` و بالا آوردن PostgreSQL و Redis:

```bash
npm run migrate
npm test
npm run check
```

سپس health/readiness و سناریوهای دو حساب واقعی باید بررسی شوند.
