# وضعیت مرحله‌های ۱ و ۲ CarMaa — نسخهٔ v4

## تغییرات این دور

- API client گسترش یافت: Q&A، پیام‌ها، اعلان‌ها، گزارش تخلف، پیشنهادهای دریافتی، نمایشگاه‌ها، امتیاز نمایشگاه و تاریخچهٔ قیمت.
- Q&A به API سرور وصل شد: فهرست و جست‌وجو، آمار دسته‌ها، سؤال‌های من، ایجاد سؤال، آپلود تصویر سؤال، پاسخ، رأی مفید با قید یکتایی دیتابیس، انتخاب پاسخ پذیرفته‌شده و شمارش بازدید محدودشده.
- مشخصات تکمیلی Q&A، تصویر، تعداد بازدید و رأی مفید با migration شمارهٔ 003 اضافه شد.
- پروفایل شخصی اکنون نام نمایشی، ایمیل، نام کاربری یکتا، آواتار و بنر را به API ارسال می‌کند. تصاویر پروفایل باید از آپلودهای مالک همان حساب انتخاب شوند.
- ثبت و ویرایش نمایشگاه به API متصل شد؛ شهر اضافه شد، نام کاربری به slug عمومی تبدیل می‌شود و لوگو/بنر از مسیر آپلود امن می‌گذرند. کد ملی در حالت API پنهان است و به سرور ارسال نمی‌شود.
- فهرست نمایشگاه‌های تأییدشده از API هیدراته می‌شود؛ نمایشگاه‌های دمو در حالت API به فهرست اصلی اضافه نمی‌شوند. دنبال‌کردن، امتیاز و اعلان‌های سروری مسیر API دارند.
- گزارش آگهی و پیشنهاد قیمت در حالت API به endpointهای سرور می‌روند و برای آگهی محلی/غیر UUID موفقیت نمایشی اعلام نمی‌شود.
- پنل اعلان‌ها در حالت API از اعلان‌های سرور استفاده می‌کند؛ خواندن، خواندن همه، پاک‌کردن و تأیید/رد پیشنهاد از API انجام می‌شود.
- نشست نامعتبر در bootstrap باعث پاک‌شدن هویت محلی موقت می‌شود تا وضعیت کاربر دیگر به‌اشتباه از مرورگر بازیابی نشود.
- افزودن تست‌های adapter فرانت‌اند و به‌روزرسانی رفتار درخواست پیام‌رسانی با `cache: no-store` و `redirect: error`.

## اعتبارسنجی قابل تکرار

- `npm test`: **۳۱ از ۳۱ موفق**
- `npm run check`: موفق
- `node --check` برای همهٔ فایل‌های JS سطح `js/`: موفق
- بررسی نحوی فایل‌های تغییرکردهٔ بک‌اند: موفق
- آزمون یکپارچهٔ PostgreSQL/Redis، migration واقعی، پیامک، درگاه sandbox، مرورگر واقعی و تست نفوذ زنده: **اجرا نشده**.

## مانع‌های باز و الزامی قبل از انتشار

1. محیط فعلی به `registry.npmjs.org` دسترسی ندارد (`EAI_AGAIN`)؛ بنابراین `npm ci`، ساخت lockfile واقعی، `npm audit` و اسکن وابستگی‌ها انجام نشده‌اند.
2. Docker/Compose، PostgreSQL و Redis در محیط فعلی نصب/در دسترس نیستند؛ migration شمارهٔ 003 روی دیتابیس واقعی اجرا نشده است.
3. برخی قابلیت‌های قدیمی هنوز کامل به API منتقل نشده‌اند: دنبال‌کردن کاربران شخصی، بخشی از آمار/تاریخچهٔ قیمت و آگهی، مدیریت کامل استوری، همهٔ فرم‌ها و برخی نماهای نمایشگاه، و پاک‌سازی/مهاجرت داده‌های دمو.
4. پنل اعلان‌های سروری به API وصل شده، اما بعضی انواع اعلان‌های legacy ممکن است دادهٔ نمایشی/ناقص داشته باشند؛ باید با دو حساب staging و پیشنهاد واقعی تست شود.
5. جریان کامل حذف حساب، درخواست‌های حریم خصوصی/دریافت داده، سیاست retention، پشتیبان‌گیری رمزگذاری‌شده و آزمون restore هنوز باید در محیط استقرار واقعی تأیید شود.
6. `package-lock.json` عمداً جعل نشده است. باید در محیط دارای دسترسی npm با `npm install --package-lock-only` ساخته و سپس `npm ci` و `npm audit` اجرا شود.

## نتیجه

این نسخه اتصال‌های بیشتری را پیاده کرده و تست‌های محلی سورس/adapter را پاس می‌کند، اما **مرحله‌های ۱ و ۲ به‌طور عملیاتی کامل و تأییدشده نیستند** تا وقتی که سرویس‌ها اجرا، migrationها اعمال و تست‌های staging انجام شوند. این سند جایگزین گزارش تست نفوذ نیست.
