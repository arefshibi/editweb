# گزارش تکمیل جریان‌های اجتماعی و آمار CarMaa — نسخه ۵

## انجام‌شده
- دنبال‌کردن کاربران شخصی با ذخیره در دیتابیس، جلوگیری از دنبال‌کردن خود، شمارنده دنبال‌کننده‌ها، فهرست دنبال‌کنندگان/دنبال‌شوندگان و اعلان سروری.
- استوری‌های ۲۴ ساعته متصل به سرور: دریافت استوری‌های فعال، انتشار تصویر از مسیر آپلود امن، پیوست اختیاری آگهی، سقف ۱۰ استوری فعال، حذف مالک‌محور و ثبت بازدید تکرارنشدنی بر اساس حساب یا شناسه دستگاه.
- شمارش بازدید استوری فقط در مسیر اختصاصی مالک برگردانده می‌شود؛ endpoint عمومی عدد بازدید را افشا نمی‌کند.
- آمار آگهی متصل به رویدادهای سرور برای بازدید، کلیک تماس و نشان‌کردن؛ نمودار ۷ و ۳۰ روزه از رویدادهای ذخیره‌شده در دیتابیس استفاده می‌کند.
- تاریخچه قیمت در صفحه آگهی‌های API با وضعیت‌های قبل/بعد و تاریخ تغییر قابل مشاهده است.
- شناسه مالک آگهی سروری به DTO فرانت‌اند افزوده شد تا پروفایل کاربر شخصی و دنبال‌کردن آن به شناسه واقعی دیتابیس متصل شوند.
- migration شماره ۰۰۴ و آزمون‌های ایستا اضافه شدند؛ cache-busting فایل‌های فرانت‌اند نیز به‌روزرسانی شد.

## اعتبارسنجی اجراشده
- `node --check` برای فایل‌های تغییریافته و `npm run check`: موفق.
- `npm test`: ۳۳ تست موفق.
- بررسی مسیرهای script در `index.html` و اعتبار ZIP پس از بسته‌بندی انجام می‌شود.

## محدودیت مهم
در این محیط PostgreSQL/Redis و مرورگر واقعی در دسترس نبودند؛ بنابراین migration ۰۰۴ روی دیتابیس واقعی اجرا نشده و مسیرهای جدید هنوز در تست یکپارچهٔ staging با دو حساب واقعی، چند دستگاه، انقضای ۲۴ ساعته و مرورگر موبایل تأیید نشده‌اند. قبل از انتشار، در staging فرمان `npm run migrate` را اجرا کنید و سناریوهای دنبال‌کردن، استوری، تاریخچه قیمت و آمار آگهی را end-to-end بررسی کنید.
