# دامنه و قوانین تست امنیتی CarMaa

## دامنهٔ فعلی
- سورس فرانت‌اند HTML/CSS/JavaScript موجود در همین مخزن.
- API در `backend/src`، migrationهای PostgreSQL، فایل‌های Docker و تنظیمات اجرایی.
- آزمون محلیِ واحد/ایستا در همین workspace.
- اسکریپت `backend/test/staging-smoke.sh` برای smoke test کم‌خطر و فقط‌خواندنی روی staging پس از راه‌اندازی.

## خارج از دامنه تا زمان تأیید مالک
- هر دامنه یا IP عمومی، محیط production، حساب کاربری/شمارهٔ تلفن واقعی، اطلاعات واقعی مشتریان و هر سرویس شخص ثالث.
- پیامک واقعی غیرآزمایشی، پول/تراکنش واقعی، آزمون فشار، brute force گسترده، حذف انبوه یا exploit مخرب.
- اسکن فعال ZAP/Nuclei یا تست نفوذ روی میزبان شبکه‌ای قبل از تعیین base URL، مجوز و بازهٔ زمانی مشخص.

## پیش‌شرط‌های آزمون staging
1. آدرس HTTPS مختص staging و فهرست originهای مجاز ثبت شود.
2. دیتابیس و Redis مستقل از production و داده‌ها کاملاً ساختگی باشند.
3. حداقل دو حساب آزمایشی A/B و نقش‌های moderator/admin از مسیر امن آماده شود.
4. پیامک و پرداخت روی sandbox/mock باشند؛ کلیدها خارج از مخزن نگه‌داری شوند.
5. نسخه/commit کد، backup و روش بازگردانی، سقف درخواست و مسئول توقف آزمون ثبت شود.
6. قبل از هر آزمون فعال، مالک محدوده و زمان را کتبی تأیید کند.

## توقف فوری
هر مشاهدهٔ دادهٔ واقعی، ارسال پیامک اشتباه، آغاز پرداخت واقعی، تأثیر روی production، خطای پایدار 5xx یا فشار بیش از سقف توافق‌شده باید موجب توقف و ثبت رخداد شود.

**وضعیت فعلی:** دامنهٔ عمومی staging از کاربر دریافت نشده؛ بنابراین این بسته فقط تست‌های محلی و بررسی ایستای سورس را اجرا کرده است. smoke test شبکه‌ای هنوز اجرا نشده است.
