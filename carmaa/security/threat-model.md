# مدل تهدید خلاصهٔ CarMaa

## دارایی‌های حساس
- شماره تلفن و چرخهٔ OTP؛ نشست‌ها و نقش مدیر/ناظر.
- آگهی‌های پیش از تأیید، شناسهٔ مالک، دلیل رد و فیلد حداقل پیشنهاد محرمانه.
- پیام‌های خصوصی، اعضای گفت‌وگو و وضعیت مسدودسازی.
- فایل اصلی/پردازش‌شدهٔ تصاویر و ارتباط عکس به مالک.
- سفارش، مبلغ، شناسهٔ authority و مرجع پرداخت.
- اطلاعات نمایشگاه، گزارش‌های تخلف، تاریخچهٔ مدیریتی و کلیدهای محیط.

## بازیگران/سطوح اعتماد
1. مهمان ناشناس: فقط فهرست عمومی آگهی‌های منتشرشده و endpoints عمومی مجاز.
2. کاربر واردشده: اطلاعات و تغییرات حساب و آگهی‌های خودش؛ فقط گفت‌وگوهایی که عضو آن‌هاست.
3. فروشنده/نمایشگاه: کنترل فقط روی منابع مالکیتی خودش؛ مجوز آگهی، نمایشگاه و تصاویر باید سمت سرور بررسی شود.
4. moderator: تصمیم‌های moderation مجاز اما نه لزوماً مدیریت secret/مدیران.
5. admin: عملیات مدیریتی حساس با audit log.
6. سرویس‌های ثالث: پیامک و درگاه پرداخت؛ پاسخ مرورگر به‌تنهایی مدرک پرداخت نیست.
7. مرورگر: محیط غیرقابل اعتماد؛ localStorage، query string و داده‌های فرم منبع حقیقت/مجوز محسوب نمی‌شوند.

## مرزهای اعتماد
- Browser → API: schema validation، session/cookie، Origin/CSRF، rate limit و کنترل مالکیت.
- API → PostgreSQL: query پارامتری، محدودیت‌های schema، تراکنش و قفل‌گذاری رقابت‌ها.
- API → Redis: rate limit مشترک؛ مسیر حساس در production هنگام خرابی Redis باید fail-closed بماند.
- API → media: بررسی magic bytes، بازپردازش تصویر، کلید تولیدشده توسط سرور و quota.
- API → SMS/payment provider: timeout، خطای provider، تکرار callback و عدم تطابق مبلغ باید fail-closed باشد.
- Public browser rendering: تمام دادهٔ قابل‌کنترل توسط کاربر باید هنگام قرارگیری در HTML/attribute/URL escape یا validate شود.

## سناریوهای با اولویت بالا
- IDOR/BOLA: تغییر شناسه برای خواندن/تغییر آگهی، تصویر، پیام، پیشنهاد یا سفارش شخص دیگر.
- ارتقای نقش یا moderation با دستکاری کلاینت؛ تأیید خودکار نمایشی نباید در حالت API کار کند.
- OTP enumeration/brute force/replay یا استفاده از کد ثابت؛ محدودیت باید در چند replica هم‌زمان باشد.
- Stored/DOM XSS از عنوان/توضیح آگهی، نام نمایشگاه، پیام یا نشانی تصویر.
- جعل/تکرار callback پرداخت و فعال‌شدن دوبارهٔ خدمت.
- آپلود بدافزار/polyglot، image bomb، دور زدن quota یا استفاده از عکس متعلق به حساب دیگر.
- افشای دادهٔ خصوصی (دلیل رد، شماره، حداقل پیشنهاد، پیام خصوصی، مختصات دقیق).
- شکست migration، پیکربندی secret ناامن یا انتشار portهای DB/Redis.

## محدودیت مدل فعلی
بخشی از تجربهٔ UI و داده‌های قدیمی هنوز محلی است. در نتیجه threat model برای بخش‌های مهاجرت‌نشده فقط مرورگر/نسخهٔ نمایشی را پوشش می‌دهد و وجود API endpoint به معنای استفادهٔ واقعی رابط از آن endpoint نیست.
